## 2. 实现

### 纯逻辑层新模块 `action_scheduler.py`（80 行，零 Qt）

两级加权随机 + 全局防重复：

```
类别级:  idle 待机 30% │ turn 转向 10% │ action 原地动作 40% │ move 移动 20%
类别内:  按动作 weight 加权（默认均匀）
```

- **类别映射**（BabyCat 无独立转向素材）：turn → walk_circle（转圈走动）；
  action → stretch/groom/spin；move → pace。素材增补后只改 `CATEGORY_ACTIONS`
- **防连续重复（全局排除）**：从所有类别剔除上一动作后再抽，类别权重自动重归一
  （刚播过 pace → move 类整体让位，20% 分摊给其余类别）
- **死锁保护**：剔除后只剩待机（素材池只有这一个动作）→ 回退允许重复
- **可注入 rng**：`pick_behavior(..., rng=random.Random(seed))`，分布可复现可统计

### main.py 接入（2676 行 ≤ T5 预算 2677）

`maybe_auto_action` 里 `random.choice(pool)` → `action_scheduler.pick_behavior(pool, self._last_auto)`；
返回 None（待机 30%）时重排定时器不播动作。净行数 **-1**（docstring 压缩 + 冗余
空池判断删除换抵 import），T5 红线 1 预算内通过。

## 3. 统计验证（tools/test_action_scheduler.py，17 断言）

2 万次采样（σ≈0.32%，容差 ≥4σ）：

| 断言 | 实测 | 理论 | 容差 |
|---|---|---|---|
| 待机占比 | 30.21% | 30% | ±1.5% |
| 转向 walk_circle | 10.13% | 10% | ±1.0% |
| 原地动作合计 | 39.96% | 40% | ±1.5% |
| stretch / groom / spin | 13.13/13.43/13.40% | 各 13.33% | ±1.0% |
| 移动 pace | 19.70% | 20% | ±1.2% |
| 概率归一 | 1.0 | 1.0 | 1e-9 |

防重复与边界：
- **防连续重复零命中**：2 万次连续采样，无一次相邻重复
- **单一选项死锁保护**：available=[stretch] + last=stretch → 56.7%（理论 4/7）
- **缺类重新归一**：pace 缺失后待机 37.79%（理论 37.5%）
- **固定种子可复现**、空池返回 None、全 0 权重退化均匀、类别内 3:1 自定义权重生效、权重 0 动作不出现

### 开发中发现并修复的真 bug

初版把 exclude 做成"类别内剔除"——`pace`、`walk_circle` 是各自类别唯一动作，
跨轮重复完全没挡住（2 万次采样出现 **1402 次连续重复**）。统计验证正是为抓这种
问题存在的。改为全局排除 + 死锁回退后零命中。
