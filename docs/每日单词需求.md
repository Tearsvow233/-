# 每日英语单词推送 — 需求定稿（2026-09-03 用户确认）

> 定位：BabyCat「M5 远期目标」之一，先于 L4 主动提醒开发。
> 状态：✅ 已与用户逐项确认（下方每行都是用户拍板过的）

## 已定决策（用户确认）

| 维度 | 决定 |
|---|---|
| 词库 | 内置**四级核心 ~2000 词**（word / 音标 / 中文释义 / 例句可选），结构必须**可换词库**（为推广/换六级留口，词库做成模块化数据文件） |
| 词量 | 用户自定义 **5~20 个/天**，默认 10 |
| 频率 | **每天只推一次**（自然日切换后重置） |
| 触发时机 | 非闹钟式。两个窗口：① 开机/启动后约 3 分钟；② 此后当天未推时，检测到系统空闲即推。**空闲就推、不避入睡** |
| 入睡协调 | 睡着时被推送：**唤醒动画 → 教词（词卡）→ 自动回到睡眠画面**；单词推送是唯一允许"唤醒入睡态"的合法动作 |
| 呈现形态 | **词卡弹窗**（暗色玻璃小卡窗，滚动列表：词+音标+释义；风格对齐现有 DIALOG_QSS 弹窗） |
| 学习深度 | v1 **只推送，无小测、无卡片刷词流** |
| 发音 | v1 **不带 TTS**（离线零依赖），展示音标 |
| 补推 | 当天错过**不补推**，次日照常 |
| 轻记录 | 「今日已推」标记 + 今日词列表留存（托盘可回看「今日单词」） |
| 开关 | 灵宠中心提供开关与词量设置（默认开启、10 词） |

## 待工程师落地的集成要点（参考既有实现）

- 空闲检测：复用入睡逻辑的 `_system_idle_sec()`（GetLastInputInfo）与 `last_touch_ts`；建议空闲 ≥ 2 分钟且当天未推即触发。
- 睡眠互操作：入睡守卫（idle_chatter/maybe_auto_action/schedule_next_auto_action 在 sleep/pending 直接 return）不得拦截单词推送；推送走独立路径：记 `was_sleeping` → `wake_up()` 流程 → 弹词卡 → 关闭后若 `was_sleeping` 恢复睡眠画面（直接置 sleep 帧/state，不重启自动定时器）。
- 每日一次：本地进度文件（建议 exe 旁 words_progress.json，跟随 settings 的 _app_dir 语义）记录 `date`/`pushed`/`words`，跨日重置。
- 选词：date 种子连续推进（按天取连续 N 词，全表轮转），避免同日重复、全表跑完约 200 天一轮。
- 词库文件：`assets/words/cet4_core.json`（结构见上），**必须同步改 BabyCat.spec 的 datas** 把该目录打进 exe；数据源优先开源词表（GitHub 走 GitCode 镜像），例句取不到就留空、UI 隐藏该行，不能因此阻塞。
- 灵宠中心：新增「每日单词」区块（启用勾选 + 词量 SpinBox 5~20 + 说明文案），settings 新增键需进 DEFAULT_SETTINGS 与 PetCenter.values() 且向后兼容。
- 托盘：新增「今日单词」入口回看当天词卡（当日已推才显示）。
- 静默模式：沿用"提醒在静默下仍生效"的既有语义，单词推送不额外制造定时器负担。
- 词卡窗口：QLabel/QListWidget 等均可被全局 DIALOG_QSS 覆盖，风格自然统一；注意窗口尺寸参考近期 PetCenter 的宽度适配经验（不要横向溢出、显示时夹回屏幕内）。
