## 逐条验收结果

### 1. MIN/MAX 生效 — PASS
- 系数 0.5 与 0.75 结果一致(89px)、2.0 与 1.25 一致(148px):双层钳制生效,极端系数不越界
- 所有 `compute_display_height()` 输出均落在 [80, 240]
- 屏不可用(None / geometry 抛异常)时安全回落到主屏基准 119px;非数值系数回落 1.0

### 2. 旧 `height` 迁移 — PASS
- 旧配置 `height: 135` → 迁移为 `height_factor ≈ 1.35` 再钳到 1.25;过大/过小 height 均被钳制
- 迁移不重置其他字段(pet_name、auto_walk 保持);无迁移键、文件缺失、JSON 损坏均安全回落默认值
- 迁移幂等,`height` 旧键不再写入新配置

### 3. 跟随当前屏计算 — PASS
- 初始高度、load 后高度均在区间内;系数变化实时反映到计算结果
- 三处 `primaryScreen()` 已全部改为 `current_screen()`(代码走查确认,main.py 221/1147/1154/1217/1398 等行)

### 4. 节流(≥4px 才重载) — PASS
- 同屏内移动、高度差 3px:不触发 `reload_sprites()`(called=0)
- 高度差 4px、大变化:各触发 1 次/累计重载,无多余重载

### 5. DPI 感知 — PASS
- dpr = 1.0 / 1.25 / 1.5 / 2.0 下,`compute_display_height()` 输出恒为同一逻辑高度(119px):逻辑尺寸不受缩放影响
- 位图物理高度 = 逻辑高度 × dpr,`setDevicePixelRatio` 已设置:物理像素充足,高 DPI 不发虚

### 6. 灵宠中心滑块 — PASS
- values() 返回 `height_factor`,0.75~1.25 各档写入正确
- 标签实时显示「当前约 97 px(本屏)· 1.10×」,范围提示文案正确

### 7. 副屏拔出 — PASS(兜底逻辑)
- `_ensure_on_screen()` 不抛异常;屏移除后宠物几何位置被钳回现存屏幕(g=349,532,screens=1)

## 遗留与建议

1. **真实双屏手动验收**(建议,非阻塞):offscreen 无法模拟双屏拖拽,请在实体双屏机上拖猫过屏一次,确认跨屏高度重算无明显卡顿、无 7 秒全量重载。
2. **T2 素材瘦身**可以开工:512 重编码后,240px 显示 × 2×DPI 仍有 6% 余量,与 T1 的 `height_factor` 上限 1.25 兼容(240×1.25 钳制后仍 ≤240,512 源图足够)。
3. 运行环境备忘:项目回归用 venv 位于 `.workbuddy/venv`(PySide6 6.11.2),PyPI 直连下载极慢,装包请用清华镜像 `https://pypi.tuna.tsinghua.edu.cn/simple`。
