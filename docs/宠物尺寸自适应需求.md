# 宠物显示尺寸：上下限 + 多屏自适应 + DPI 感知

> 目标：**用户体验优先、项目完整**。小江在任何屏幕（小屏笔记本 / 4K 大屏 / 副屏 / 混合 DPI）上都落在合理体型区间内，且高 DPI 下不模糊。
> 决策来源：用户 2026-09-04 拍板（对比竞品 dsh-pet 后的优化项之一）。

---

## 1. 决策定稿

| 项 | 取值 | 理由 |
|---|---|---|
| 显示高度下限 `MIN_H` | **80 px** | 低于此值五官表情已看不清，失去陪伴感 |
| 显示高度上限 `MAX_H` | **240 px** | 4K（2160 高）屏上仍只占约 11%，不喧宾夺主 |
| 自适应基准 | `round(当前屏可用高度 × 0.11)` | 1080p→118px、1440p→158px、4K→237px，天然落在上下限内 |
| 用户微调 | **相对系数** `height_factor`，范围 **0.75 ~ 1.25**，默认 1.0 | 换屏后按新屏重算，用户偏好不丢失 |
| 最终公式 | `h = clamp(round(screen_avail_h × 0.11 × height_factor), 80, 240)` | 双层钳制：系数再极端也不越界 |
| 素材源规范 | **512 px**（覆盖 240px 显示 × 2 倍 DPI，留 6% 余量） | 体积 135MB→~63MB，单帧位图内存 −75% |

## 2. 现状问题（代码侧，本轮必须修）

1. **主屏写死**：`main.py` 有三处 `QApplication.primaryScreen().availableGeometry()`（约 1027 / 1095 / 1990 行）——初始定位、`recentre()`、边界钳制全按主屏算。宠物被拖到副屏后，边界判定与"唤回"都会算错屏。
2. **非 DPI 感知**：`reload_sprites()` 里 `p.scaledToHeight(h)` 按**逻辑像素**缩放，在 125%/150%/200% 缩放的高 DPI 屏上，Qt 会把位图再放大一次 → **发虚**。
3. **无成文上下限语义**：设置面板 `QSpinBox(60, 240)` 是硬编码区间（约 515 行），换屏不重算，也没有"自适应"概念。
4. **冷启动慢**：500 帧全量解码 + 缩放约 7.4 秒（实测），且换屏重算尺寸会触发 `reload_sprites()` 全量重载 → 必须加**节流**，否则拖到副屏会卡 7 秒。

## 3. 本轮实现范围（代码侧）

### 3.1 常量与设置项
- 模块级 `MIN_PET_H = 80` / `MAX_PET_H = 240` / `PET_H_RATIO = 0.11`
- `DEFAULT_SETTINGS` 新增 `height_factor: 1.0`（默认）
- 兼容迁移：旧配置若只有 `height`（如 100），迁移为 `height_factor = clamp(height / 当前屏基准, 0.75, 1.25)`；读不到屏时退化为 1.0
- 保留 `height` 键的读取兼容，避免老 `settings.json` 报错

### 3.2 尺寸计算与多屏
- 新增方法 `current_screen()`：优先 `self.screen()`，为 None 时回落 `QApplication.primaryScreen()`
- 新增 `compute_display_height(screen=None)`：按 §1 公式返回钳制后的高度
- **三处 `primaryScreen()` 全部改为 `current_screen()`**
- 监听 `QApplication.screenAdded` / `screenRemoved`，以及窗口 `moveEvent` 中检测所在屏变化：
  - 屏变化 → 重算高度 → **仅当新高度与当前高度相差 ≥4px 才触发重载**（节流，防拖屏卡顿）
  - 屏被移除（副屏拔出）→ 把宠物钳回有效区域；若已不在任何屏内，调用 `recentre()` 唤回

### 3.3 DPI 感知
`reload_sprites()` 的 `load()` 改为：
```python
dpr = self.devicePixelRatioF() or 1.0
pm = src.scaledToHeight(int(round(h * dpr)), Qt.TransformationMode.SmoothTransformation)
pm.setDevicePixelRatio(dpr)   # 逻辑尺寸仍是 h，物理像素按 dpr 提供 → 高 DPI 不糊
```

### 3.4 设置面板（灵宠中心）
- "显示高度 px" 的 `QSpinBox` → 改为**体型滑块**：范围 0.75×~1.25×，步进 0.05，实时显示"当前约 xxx px（本屏）"
- 滑块下方小字标注：`范围 80 – 240 px · 随屏幕自动适配`
- 保存时写 `height_factor`，`values()` 返回新字段（约 743 / 760 行附近同步）

### 3.5 不改的部分
- 素材文件本轮**不动**（512 规范 / 图集化 / 预缩放缓存见 §4，下一轮）
- 动作调度、提醒、单词推送等逻辑不受影响

## 4. 后续轮次（素材侧，已拍板）

按顺序执行：
1. **源图降到 512 规范** —— 批量重编码 500 帧，**先备份** `assets/sprites` 原图
2. **图集化 sprite sheet** —— 500 个散文件合并为按动作分组的图集，减少冷启动文件 IO
3. **预缩放缓存** —— 首次启动后按当前显示高度缓存小图，二次启动目标 <1s（现状 7.4s）

## 5. 验收基线

- [ ] `MIN_PET_H`/`MAX_PET_H` 生效：任何屏幕、任何 factor 下，实际显示高度 ∈ [80, 240]
- [ ] 副屏场景：宠物拖到副屏后，边界钳制与 `recentre()` 都按**副屏**几何计算
- [ ] 副屏拔出：宠物被钳回主屏，不丢失、不越界
- [ ] DPI：150% 缩放下位图按物理像素提供，放大观察不发虚（截图比对）
- [ ] 节流：同一屏内反复移动不触发重载；跨屏且高度差 ≥4px 才重载
- [ ] 设置面板：滑块可调，`values()` 返回 `height_factor`，关闭后重开保持
- [ ] 旧 `settings.json`（只有 `height`）能正常迁移，不报错、不重置其他字段
- [ ] 现有测试无回归：`tools/dev_smoke.py` / `qa_extra_smoke.py` / `test_word_push.py` / `test_chat_input_title.py`
