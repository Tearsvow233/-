# T3 预缩放缓存 — 验收报告

> 验收日期:2026-09-07 · 对应需求:`docs/宠物尺寸自适应需求.md` §4「后续轮次(素材侧)」第 3 项
> 目标:首次启动后按当前显示高度缓存小图,**二次启动 <1s(现状 7.4s)**
> 验收用例:`tools/test_sprite_cache.py` · 耗时探针:`tools/probe_startup.py`

## 结论:**通过(超额达标)**

二次启动实际 **0.15~0.21s**(目标 <1s),加速 **~15 倍**;冷启动也从 7.4s 降到 ~3.1s(T2 素材瘦身 + 本轮缓存共同贡献)。

## 实测数据

| 场景 | 耗时 | 说明 |
|---|---|---|
| 冷启动(T2 后,无缓存) | 3.08s + 后台构建 0.78s | 前台不阻塞,缓存后台分批写盘 |
| 二次启动(命中缓存) | **0.21s** | 跨进程实测 |
| 三次启动 | **0.15s** | 系统文件缓存热 |
| 换高度/换屏重载(缓存命中) | 0.22s | vs 未命中 2.79s,加速 12.7× |
| 缓存磁盘占用 | **4 MB** | 500 帧 @ 88px 物理高度 |

## 关键发现:瓶颈不在解码,在「每文件加载开销」

微基准(500 帧,offscreen):

| 操作 | 耗时 |
|---|---|
| 解码 512 源图(500 个文件) | 3.00s |
| 缩放 500 帧 | **0.05s** |
| 读回 500 个单帧缓存 PNG | 4.37s(反而更慢!) |
| 横幅图读回+切片+缩放(60 帧) | 0.26s |

每次 `QPixmap(文件)` 有 ~6ms 固定开销(文件打开 + Qt 插件解析等),与文件大小无关。所以**逐帧文件缓存毫无意义**,必须减少文件数——最终方案是 **sprite strip(横幅图)缓存**。

## 实现方案

### 缓存布局

```
cache/sprites/h{物理像素高度}/     ← 缓存 key = round(显示高 × DPR)
    strip_0000.png               ← 横幅图,8192px 宽度上限自动分片
    strip_0001.png
    ...(500 帧 @ 88px → 6 个文件)
    manifest.json                ← 源素材指纹 + 每帧在 strip 中的 [x,y,w,h]
```

### 工作流程

1. **命中**:`manifest 指纹匹配 + strip 文件齐全` → 一次读入十几条 strip,`copy()` 切帧,补 DPR 标记
2. **未命中**:照旧从源图加载(不慢于改造前),加载完成后 QTimer 每 5ms 拼**一条** strip 写盘,不卡 UI
3. **失效**:任一源帧 size/mtime 变化(T2 重编码等)→ 指纹不匹配 → 自动重建
4. **清理**:构建完成后删除其他高度的缓存目录,磁盘始终只保留一代(4MB)
5. **兜底**:缓存读取异常时自动回退源图加载,删除 `cache/` 目录即可彻底重置

### 代码改动(main.py)

- 常量:`SPRITES_CACHE_DIR = APP_DIR / "cache" / "sprites"`(exe 旁可写位置,不进只读的 `_MEIPASS`)
- `reload_sprites()`:优先走缓存,未命中收集物理尺寸帧供后台构建
- 新增:`_frame_names` / `_cache_signature` / `_cache_ready` / `_load_cache_pixmaps` / `_schedule_cache_build` / `_cache_build_tick` / `_prune_old_cache`

## 验收基线对照

- [x] 首次启动后按当前显示高度缓存小图 → strip 缓存,后台分批构建(前台不阻塞)
- [x] 二次启动 <1s → 实测 0.15~0.21s
- [x] 8192px 宽度分片 → 规避 Qt 纹理宽度限制(32767),pace 192 帧 @480px 也能安全分片
- [x] 高度变化(≥4px 节流重载)后重新构建 → 新 h 目录 + 旧目录自动清理
- [x] 源素材更新 → 指纹失效自动重建
- [x] 高 DPI:缓存按物理像素(显示高 × DPR)存,读回补 DPR 标记,不发虚

## 遗留与建议

1. **打包注意**:PyInstaller 打包时把 `cache/` 加入排除,避免把开发机缓存带进发布包(`BabyCat.spec` 的 `excludes` 或直接不收集该目录)。
2. **可选优化**:冷启动 3.08s 里 PetAI/提醒调度等初始化占一部分;素材加载本身 ~2.8s 仍是 500 文件逐个解码。如需进一步压缩冷启动,可做 T2.5 图集化(源素材本身合并),但二次启动已达标,优先级低。
3. strip 拼接用 `QPainter.drawPixmap`,帧间 1 像素重叠未见(同一 strip 内帧连续无缝);如有极细缝隙可改用 `copy()` 整块切。
