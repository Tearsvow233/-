## 验收标准（交接包原文）

> `main.py` 行数预算断言 + 纯逻辑层禁 Qt 的断言就位

参照原项目（DeepSeek Harness）`tests/test_architecture.py` 的做法，落地为本项目结构。

## 分层现状（红线管辖范围）

| 层 | 文件 | 行数 | 约束 |
|---|---|---|---|
| UI 层 | main.py | 2677 | 行数预算 2677，**只许降不许涨** |
| UI 层 | word_push.py | 333 | 允许 Qt；禁访问 main 私有面 |
| 纯逻辑层 | ai_chat.py | 312 | 禁 Qt；禁反向依赖 UI 层 |
| 纯逻辑层 | reminder_parser.py | 225 | 禁 Qt；禁反向依赖 UI 层 |

依赖方向唯一合法：**UI 层 → 纯逻辑层**。

## 五条红线（tools/test_architecture.py，13 断言全过）

1. **行数预算**：`main.py` ≤ 2677 行（2026-09-07 基线快照）。超出即 FAIL，
   提示拆分到纯逻辑层模块。
2. **纯逻辑层禁 Qt**：AST 级扫描 `ai_chat.py` / `reminder_parser.py` 的全部
   import 节点（含函数内、条件内 import），命中 PySide6/PyQt5/PyQt6/shiboken
   即 FAIL。比 grep 强，抓得住 `if True: from PySide6 import ...`。
3. **禁反向依赖**：纯逻辑层禁止 import `main` / `word_push`。
4. **main 私有面跨模块访问零命中**：其他生产代码模块不得访问 `main._xxx`
   （dunder 除外）。当前天然零命中——红线的意义就是保持为零。
5. **断言器自测（防恒过）**：用临时伪造文件证明检查器确实能抓到
   "函数内 Qt import" 和 "main._xxx 私有访问"，且干净文件不误报。
   静默失效的红线比没有红线更危险，所以检查器本身也被测试。

## 白名单维护

新增纯逻辑模块时，把文件名加进 `tools/test_architecture.py` 顶部的
`PURE_LOGIC_MODULES` 即自动纳入红线管辖（禁 Qt + 禁反向依赖 + 私有面检查）。
`MAIN_PY_LINE_BUDGET` 在 main.py 瘦身后应手动收紧到新的当前值。
