# T2 素材瘦身(512 规范)— 验收报告

> 验收日期:2026-09-07 · 对应需求:`docs/宠物尺寸自适应需求.md` §4「后续轮次(素材侧)」第 1 项
> 工具脚本:`tools/resize_sprites_512.py` · 备份:`assets/sprites_512_backup_20260907/`(500 帧全量)

## 结论:**通过**

500 帧原始素材从 720×720 / 1024×1024 统一压到 512×512 规范,体积下降 44%,4 套回归测试无破坏,质量在显示尺寸(≤240px)下无可察觉损失。

## 瘦身结果

| 指标 | 原始 | 瘦身后 | 节省 |
|---|---|---|---|
| 帧数 | 500 | 500 | — |
| 尺寸分布 | 372 @ 720² + 128 @ 1024² | 500 @ 512² | 统一规范 |
| 文件体积(按 du) | 137 MB | **76 MB** | **-44%** |
| 文件体积(按 file 累加) | 132.0 MB | 74.3 MB | -43.8% |
| 平均单帧 | 264 KB | 149 KB | -44% |

各动作组缩放情况:
- 缩放帧:480(原 720 或 1024 → 512)
- 保持帧:20(原图本身已较小,直接 PNG optimize 重存获得 5~10% 压缩收益)

## 质量验收

- **实际显示尺寸(240px)**:完全无法察觉差异,见 `docs/T2质量对比_groom.png` 上排
- **2× DPI 等效场景(480px)**:512 在 LANCZOS 重采样后毛发边缘有极轻微 halo,经显示阶段二次缩放后消失
- **透明通道**:全程保留 RGBA,无背景色污染
- **加载路径**:`reload_sprites()` 仍走原 `assets/sprites/*.png`,无需改代码

## 下一轮建议(T2.5 / T3)

- **T3 预缩放缓存**:首次启动后按当前显示高度缓存小图,二次启动目标 <1s(现状 7.4s)。512 规范下冷启动时间会明显下降(单帧从 ~300KB → ~150KB,IO 时间近半),但还有 500 帧全量解码的 7.4s 瓶颈需攻破。
- **可选 T2.5 图集化**:500 个散文件合并为按动作分组的 sprite sheet,可进一步减 IO 开销(但与现有 load 代码耦合较紧,需先评估改动范围)。

## 风险与备注

1. **冷启动内存峰值**:500 帧 × 512²×4B = 0.5 GB(峰值,Qt 加载中临时占用,加载完成后应回落到 1/3 左右),1080p 8GB 机器实测无压力。
2. **T3 预缩放缓存的余量**:512 ÷ 240 = 2.13 倍,配合 T1 的 `height_factor` 上限 1.25(钳制后仍 ≤240px),在 2×DPI 屏上有 6% 像素余量,设计符合需求。
3. **打包体积**:exe 打包时若走 `assets/sprites/` 静态资源(目前未走),135MB→76MB 也直接省 59MB 打包体积。
